
## Core attention algorithm & type

|Param|Purpose|Options / meaning|
|---|---|---|
|`attention`|Which **implementation/algorithm** computes attention scores (the "how").|`'autoselected'` (let MaxText pick based on hardware/config), `'dot_product'` (plain unfused JAX attention — slowest, most flexible/debuggable), `'flash'` (Pallas-based Flash Attention, TPU), `'cudnn_flash_te'` (NVIDIA cuDNN Flash Attention via TransformerEngine, GPU). Default `'autoselected'`.|
|`attention_type`|Which **variant/pattern** of attention the model uses (the "what pattern of tokens attend to what").|`'global'` (every token attends to all prior tokens — standard causal attention), `'local_sliding'` (attend only within a sliding window), `'chunk'` (chunked attention), `'mla'` (Multi-head Latent Attention, DeepSeek-style), `'full'`, `'compressed'` (Compressed Attention), `'block_diffusion'` (block-causal, for diffusion-style training). Default `'global'`.|
|`share_kv_projections`|Whether K and V share the same projection weights (a parameter-saving variant). **Not compatible with `attention_type='mla'`.**|`true`/`false`, default `false`.|
|`attention_bias`|Adds a learnable bias to the Q/K/V projections.|`true`/`false`, default `false`.|
|`attention_sink`|Enables attention sink tokens (fixed tokens that always remain attendable regardless of sliding-window/context truncation — helps stabilize long-context/streaming generation).|`true`/`false`, default `false`.|
|`sliding_window_size`|Window size for `attention_type='local_sliding'`.|Integer, default `0` (unused unless local sliding is active).|
|`chunk_attn_window_size`|Window size for `attention_type='chunk'`.|Integer, default `0`.|
|`causal_block_size`|Token block size B for block-causal attention used by Block Diffusion ([arXiv:2503.09573](https://arxiv.org/abs/2503.09573)) — tokens attend bidirectionally _within_ a block, and causally _across_ blocks.|Integer, default `32`.|

## Logit stabilization & normalization

|Param|Purpose|Options / meaning|
|---|---|---|
|`attn_logits_soft_cap`|Soft-caps attention logits (à la Gemma2) to prevent them from growing unboundedly large before the softmax — a smooth alternative to hard clipping.|Float, default `0.0` = disabled.|
|`final_logits_soft_cap`|Same idea, applied to the final output logits before the loss.|Float, default `0.0` = disabled.|
|`z_loss_multiplier`|Weight for a z-loss auxiliary term that penalizes the log-sum-exp of the logits growing too large — another logit-stabilization technique (used in PaLM, etc.).|Float, default `0.0` = disabled.|
|`use_post_attn_norm`|Applies a normalization layer _after_ the attention block (in addition to/instead of pre-norm), as some architectures do.|`true`/`false`, default `false`.|
|`use_post_ffw_norm`|Same, applied after the feed-forward block.|`true`/`false`, default `false`.|
|`v_norm_with_scale`|Whether the value-vector normalization (when used) includes a learnable scale parameter.|`true`/`false`, default `true`.|
|`qk_norm_with_scale`|Whether QK-normalization (normalizing queries/keys before the dot product, a stability technique some recent architectures use) includes a learnable scale parameter.|`true`/`false`, default `true`.|

## Gemma4-small-specific (Per-Layer Embeddings & KV sharing)

|Param|Purpose|Options / meaning|
|---|---|---|
|`hidden_size_per_layer_input`|When positive, each decoder layer adds an extra "Per-Layer-Embedding" sub-block at the end (see `models/gemma4_small.py`) — a Gemma4 E2B/E4B-specific mechanism.|Integer, default `0` = disabled.|
|`vocab_size_per_layer_input`|Companion vocab size for that per-layer-embedding mechanism.|Integer, default `0`.|
|`num_kv_shared_layers`|Number of _trailing_ decoder layers that reuse K/V projections from the last non-shared layer _of the same attention type_ (sliding↔sliding, full↔full) — those layers skip having their own K/V projections entirely.|Integer, default `0` = disabled.|
|`use_double_wide_mlp`|When `true`, KV-shared layers double their MLP intermediate size, to compensate for the parameter budget "saved" by not having their own K/V projections.|`true`/`false`, default `false`.|

## MLA (Multi-head Latent Attention)

MLA is DeepSeek's attention variant: instead of caching full K/V per head, it compresses K/V into a shared low-rank latent vector (dramatically shrinking the KV cache), then reconstructs per-head K/V from it on the fly.

|Param|Purpose|Options / meaning|
|---|---|---|
|`q_lora_rank`|Low-rank dimension for the query's LoRA-style compression.|Integer, default `0` = query LoRA compression disabled (full-rank query projection).|
|`kv_lora_rank`|Low-rank dimension of the compressed KV latent — this is what actually gets cached, so it's the main lever on KV-cache memory savings.|Integer, default `512`.|
|`qk_nope_head_dim`|Head dimension of the "no positional encoding" (NoPE) portion of the query/key.|Integer, default `128`.|
|`qk_rope_head_dim`|Head dimension of the RoPE (rotary positional encoding) portion of the query/key — MLA splits Q/K into a NoPE part and a RoPE part.|Integer, default `64`.|
|`v_head_dim`|Value head dimension.|Integer, default `128`.|
|`use_sliced_mla_proj`|Whether to slice the projection kernel weights _before_ the contraction in MLA, instead of running the full projection and then `jnp.split`-ing the result.|`true`/`false`, default `false`. A kernel-efficiency knob, not a correctness one.|
|`mla_naive_kvcache`|Whether MLA uses the "naive" (uncompressed, full per-head) KV cache representation internally rather than caching the compressed latent directly.|`true`/`false`, default `true`.|

## MoBA (Mixture of Block Attention)

An efficient sparse-attention mechanism from Moonshot AI ([tech report](https://github.com/MoonshotAI/MoBA/blob/master/MoBA_Tech_Report.pdf)) — splits the sequence into blocks and routes each query to only its top-k most relevant blocks, rather than attending to the full sequence.

|Param|Purpose|Options / meaning|
|---|---|---|
|`moba`|Master switch for MoBA.|`true`/`false`, default `false`.|
|`moba_chunk_size`|Size of each attention block/chunk.|Integer, default `1024`.|
|`moba_topk`|Number of top blocks each query attends to.|Integer, default `8`.|

## DeepSeek Sparse Attention (DSA) / Indexer

DeepSeek-V3.2 introduces an "indexer" module inside MLA that learns to select a sparse top-k subset of tokens each query should actually attend to, rather than attending densely.

|Param|Purpose|Options / meaning|
|---|---|---|
|`use_indexer`|Master switch for the DSA indexer.|`true`/`false`, default `false`.|
|`indexer_head_dim`|Head dimension used inside the indexer module.|Integer, default `128`.|
|`indexer_n_heads`|Number of indexer heads.|Integer, default `64`.|
|`indexer_topk`|How many tokens the indexer selects for each query to actually attend to.|Integer, default `2048`.|
|`indexer_use_approx_top_k`|Uses an approximate (rather than exact) top-k selection algorithm for speed.|`true`/`false`, default `false`.|
|`indexer_approx_top_k_recall`|Target recall for the approximate top-k algorithm, when enabled.|Float, default `0.95`.|
|`indexer_mask_exact_topk`|Whether to mask to the exact top-k set (as opposed to a looser threshold) when computing the indexer's attention mask.|`true`/`false`, default `true`.|
|`indexer_sparse_training`|Selects the indexer's training strategy. `false` = **Dense Warm-up**: indexer loss computed over _all_ tokens (typically paired with `trainable_parameters_mask` to freeze the rest of the model while warming up the indexer). `true` = **Sparse Training**: indexer loss computed only over the top-k tokens, with the indexer's input detached so it optimizes independently. Only active when `indexer_loss_scaling_factor > 0`.|`true`/`false`, default `false`.|
|`indexer_loss_scaling_factor`|Multiplier for the indexer's KL-divergence auxiliary loss.|Float, default `0.0` = disabled.|

## QK-Clip (Muon Clip)

A stabilization technique (associated with the Muon optimizer / "MuonClip") that clips query-key logits to prevent attention-score blowup during training — notably used by Kimi K2.

|Param|Purpose|Options / meaning|
|---|---|---|
|`use_qk_clip`|Enables QK-Clip. Supported with MLA combined with either the DotProduct or Tokamax Splash attention implementations.|`true`/`false`, default `false`.|
|`qk_clip_threshold`|The clipping threshold (τ in the paper).|Float, default `100.0`.|

## Notes to self

- `attention` (the kernel/algorithm) and `attention_type` (the pattern) are independent axes — e.g. you could run `attention_type='mla'` with `attention='dot_product'` for debugging, then switch to a fused kernel for speed once correctness is verified.
- MLA's `kv_lora_rank` is the single most important number for understanding _why_ MLA saves memory — it's the size of what actually goes in the KV cache, versus the much larger `num_kv_heads × head_dim` you'd cache with standard attention.
- DSA's indexer training modes (`indexer_sparse_training` false vs. true) map onto a two-phase recipe: warm up the indexer densely first (with the rest of the model frozen via `trainable_parameters_mask`), then switch to sparse training once the indexer is good enough to trust for token selection.
- Splash-attention kernel tuning (`sa_block_q`, `sa_block_kv`, etc.) and context-parallelism strategy live physically further down the file, alongside the mesh/sharding config — those get covered in Part 7 since they're really about _how_ these attention patterns get executed across devices, not _which_ pattern is used.
