## Checkpointing

MaxText's checkpoint loading logic follows a strict priority order, worth internalizing before the individual params:

1. If a checkpoint already exists for `run_name` → load the **latest full checkpoint** (this is what makes preemption-recovery automatic).
2. Otherwise, exactly one of:
    - `load_parameters_path` set → load **params only** (no optimizer state) — used to initialize from a pretrained checkpoint for fine-tuning.
    - `load_full_state_path` set → load **params + optimizer state + step count** — used to continue a training run from a specific path rather than relying on auto-resume.
3. If none of the above → initialize from scratch.

These two path options are mutually exclusive — setting both is invalid.

## Notes to self

- The `load_parameters_path` vs `load_full_state_path` distinction maps directly onto "fine-tune from a pretrained checkpoint" vs. "resume my own interrupted training run" — a common point of confusion.
- `async_checkpointing` + `checkpoint_storage_concurrent_gb` + the OCDBT/Zarr3 flags are all about hiding checkpoint I/O latency behind compute at scale — matters a lot more once checkpointing multi-billion-parameter models across many hosts.
