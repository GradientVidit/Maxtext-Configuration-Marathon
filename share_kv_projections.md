## 1. Why does `share_kv_projections` exist?

In standard Multi-Head and Grouped-Query Attention, Key ($K$) and Value ($V$) representations are generated by two separate linear projection weight matrices:

$$\text{Standard:}\quad K = X W_k,\quad V = X W_v \quad (W_k, W_v \in \mathbb{R}^{d_{model} 	imes d_{kv}})$$

In compact or parameter-constrained architectures, $K$ and $V$ can share a single projection matrix:

$$\text{Shared:}\quad K = V = X W_{kv} \quad (W_{kv} \in \mathbb{R}^{d_{model} 	imes d_{kv}})$$

```text
Standard Projections (3 Matmuls / Layer):
  Q = X · W_q    [d_model → d_q]
  K = X · W_k    [d_model → d_kv]
  V = X · W_v    [d_model → d_kv]

Shared KV Projections (share_kv_projections=True):
  Q = X · W_q    [d_model → d_q]
  K = V = X · W_kv [d_model → d_kv]  <-- Saves 1 entire projection weight per layer
```

This reduces parameter count by $d_{model} 	imes d_{kv}$ per attention layer and cuts one GEMM during projection.

---

## 2. Options & Defaults

| Value | Behavior | Parameter Impact |
|---|---|---|
| `false` | Independent $W_k$ and $W_v$ weight tensors. | Standard parameter count. **Default**. |
| `true` | Single $W_{kv}$ weight tensor shared between Key and Value. | Reduces projection weights by $d_{model} 	imes (N_{kv} 	imes d_{head})$ per layer. |

Default in `base.yml`: `false`

---

## 3. The MLA Incompatibility Rule

Multi-Head Latent Attention (`attention_type='mla'`) compresses $K$ and $V$ into a joint latent vector $c_{kv} \in \mathbb{R}^{d_c}$, but then projects $c_{kv}$ into separate $K_{nope}$ and $V$ vectors via distinct up-projection matrices $W_{UK} \in \mathbb{R}^{d_c 	imes d_k}$ and $W_{UV} \in \mathbb{R}^{d_c 	imes d_v}$, plus a separate decoupled RoPE key $K_{rope} = X W_{KR}$.

Because MLA's mathematical formulation relies on independent NoPE and Value projections from the latent space, setting `share_kv_projections=true` alongside `attention_type='mla'` is **invalid and rejected by MaxText configuration validation**.

## 4. Interactions with other parameters

| Related Parameter | Interaction |
|---|---|
| [[attention_type]] | Fully compatible with `'global'`, `'local_sliding'`, `'chunk'`. Incompatible with `'mla'`. |
| [[base_num_kv_heads]] | Determines the number of shared heads produced by $W_{kv}$. |
| [[fused_qkv]] | When `share_kv_projections=true`, fused projection layout concatenates $[W_q, W_{kv}]$ instead of $[W_q, W_k, W_v]$. |
| [[num_kv_shared_layers]] | Orthogonal concept: `share_kv_projections` shares weights *within a layer* ($K \leftrightarrow V$), whereas `num_kv_shared_layers` shares KV projections *across adjacent decoder layers*. |

---

## 5. Practical Scenarios

- **Standard Pretraining (LLaMA / Gemma / Mistral):** Leave `share_kv_projections: false`. Key representations (content addressing) and Value representations (content retrieval) benefit from independent feature spaces.
- **Extreme Parameter Compression / Mobile Models:** Set `share_kv_projections: true` when pruning parameters for edge deployment where memory footprint is strictly bounded.
- **Reproducing Specific Shared-KV Models:** Required when loading pretrained checkpoints from architectures designed with tied KV projections.

---

### One-line intuition

> **`share_kv_projections=true` forces Keys and Values within an attention layer to share a single projection matrix $W_{kv}$, saving parameters at the expense of decoupling addressing from retrieval.**
