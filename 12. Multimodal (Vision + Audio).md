
This part covers the full multimodal config block, plus a handful of adjacent params (chunked prefill, prefix caching, Llama4-specific attention tweaks, NNX) that live in the same stretch of the file without being multimodal themselves.

## Chunked prefill

Splits a long prefill into smaller chunks processed sequentially, rather than one large prefill pass — reduces peak memory and can improve time-to-first-token in serving contexts.

|Param|Purpose|Options / meaning|
|---|---|---|
|`prefill_chunk_size`|Size of each prefill chunk.|Integer, default `256`.|
|`use_chunked_prefill`|Master switch.|`true`/`false`, default `false`.|

## Prefix caching (JetStream)

Caches KV-cache prefixes shared across requests (e.g. a common system prompt) so they don't need to be recomputed per-request — a JetStream serving feature.

|Param|Purpose|Options / meaning|
|---|---|---|
|`enable_prefix_caching`|Master switch.|`true`/`false`, default `false`.|
|`prefix_caching_hbm_byte`|HBM budget allocated for the prefix cache.|Integer (bytes), default `10_000_000_000` (10 GB).|
|`prefix_caching_dram_byte`|Host DRAM budget allocated for the prefix cache (a larger, slower overflow tier beyond HBM).|Integer (bytes), default `100_000_000_000` (100 GB).|

## Llama4-specific attention tweaks

|Param|Purpose|Options / meaning|
|---|---|---|
|`use_qk_norm`|Whether to apply query/key normalization. Architecture-dependent placement: non-Llama4 models that use QK-norm apply RMSNorm _before_ RoPE, while Llama4 applies L2-norm _after_ RoPE.|`true`/`false`, default `false`.|
|`nope_layer_interval`|Every `X` layers skip RoPE entirely (NoPE = No Positional Embedding layers), Llama4-style.|Integer, default `-1` = disabled (every layer uses RoPE).|
|`interleave_moe_layer_step`|Every `X` layers is an MoE layer (the rest being dense) — a simple periodic interleaving pattern, as opposed to the more general `inhomogeneous_layer_cycle_interval` mechanism from Part 5 for irregular patterns.|Integer, default `1` (every layer is MoE, if MoE is enabled at all).|
|`temperature_tuning`|Dynamically scales the attention temperature per query token based on sequence length. Recommended for long sequences (>32k tokens) to keep outputs stable. See [arXiv:2501.19399](https://arxiv.org/abs/2501.19399).|`true`/`false`, default `false`.|

## M-RoPE (Multimodal RoPE)

Extends RoPE to jointly encode positions across text, image, and video/temporal dimensions in a unified rotary scheme (used by Qwen2-VL-style and Qwen3-Omni-style models).

|Param|Purpose|Options / meaning|
|---|---|---|
|`use_mrope`|Master switch for M-RoPE.|`true`/`false`, default `false`.|
|`mrope_section`|How the rotary dimension budget is split across the temporal/height/width position components.|List of integers, default `[24, 20, 20]`.|
|`position_id_per_seconds`|How many position IDs correspond to one second of audio/video — ties the temporal RoPE component to real playback time.|Integer, default `25`.|

## Notes to self

- The vision/audio config is really **two parallel, model-family-specific parameter sets** (Llama4's ViT vs. Qwen3-OmniMoE's ViT+audio) coexisting in one flat namespace, distinguished only by the `_for_vit`/`_for_audio` suffix convention — worth remembering that setting `hidden_size_for_vit` on a Qwen3-Omni run, for instance, may simply be a no-op if that model's code path reads different config keys.
- `freeze_vision_encoder_params`/`freeze_audio_encoder_params` defaulting to `true` reflects the standard multimodal-training recipe: bring in a pretrained vision/audio encoder, keep it frozen, and only train the LM + the projector that bridges the two — unfreezing is the exception, not the rule.
- M-RoPE's `mrope_section: [24, 20, 20]` (temporal/height/width split) is worth connecting back to Part 3's `head_dim` — the three numbers here need to sum to (at most) half the head dimension being used for rotary position encoding, since RoPE operates on pairs of dimensions.
- `enable_nnx`/`pure_nnx`/`pure_nnx_decoder` all defaulting to `true` is a signal MaxText has essentially completed its NNX migration — worth being aware if you're reading older MaxText code/docs that still reference Linen-style patterns, since they may be describing a path that's no longer the default.
