## Dataset — batch sizing & packing

| Param | Purpose | Options / meaning | Deep Dive |
|---|---|---|---|
| `per_device_batch_size` | Training batch size per device. Can be fractional (see `expansion_factor_real_data` below for why). | Float, default `12.0`. | [[per_device_batch_size]] |
| `expansion_factor_real_data` | Controls how many hosts actually load data vs. how much each loading host reads. When `>1`: `total_hosts // expansion_factor_real_data` hosts load data, each reading `per_device_batch_size * expansion_factor_real_data`. When between `0` and `1`: lets Grain read a checkpoint saved by a job with a larger chip count using a smaller chip count. ([details](https://github.com/AI-Hypercomputer/maxtext/blob/main/docs/guides/data_input_pipeline/data_input_grain.md#using-grain)) | Float, default `-1.0` = disabled/not applicable. | [[expansion_factor_real_data]] |
| `eval_per_device_batch_size` | Eval batch size per device. | Float, default `0.0` = not set (falls back to using the training batch size). | [[eval_per_device_batch_size]] |
| `max_corpus_chars` | Cap on how many characters of raw corpus text to load (a dataset-size safety valve, mainly for TFDS-style pipelines). | Integer, default `10_000_000`. | [[max_corpus_chars]] |
| `train_data_columns` | Which column(s) of the dataset to use as training input. For DPO datasets this would instead point at `"chosen"`/`"rejected"` columns. | List, default `['text']`. | [[train_data_columns]] |
| `train_image_column` | Column name for image data in multimodal training sets. | String, default `'image'`. | [[train_image_column]] |
| `eval_data_columns` | Same as `train_data_columns`, for eval. | List, default `['text']`. | [[eval_data_columns]] |
| `eval_image_column` | Same as `train_image_column`, for eval. | String, default `'image'`. | [[eval_image_column]] |
| `packing` | Whether to pack multiple shorter examples into a single fixed-length sequence (avoids wasting compute on padding). | `true`/`false`, default `true`. | [[packing]] |
| `num_epoch` | Number of epochs to iterate over the dataset. | Integer, default `1`. | [[num_epoch]] |
| `generate_padding_batch_train` | Whether to generate a padding batch (dummy batch to keep step counts/shapes consistent) for training. | `true`/`false`, default `false`. | [[generate_padding_batch_train]] |
| `generate_padding_batch_eval` | Same, for eval. | `true`/`false`, default `false`. | [[generate_padding_batch_eval]] |
| `max_segments_per_seq` | Maximum number of packed segments allowed in a single sequence. Needs to be passed to TransformerEngine's `DotProductAttention` layer for packing support — TE can crash or corrupt data if more segments are packed than this specifies. Recommended to set to something like `32` for GPUs using TransformerEngine. | Integer, default `-1` (unset/unbounded). | [[max_segments_per_seq]] |

## Batch-size ramp-up

Analogous to Megatron-LM's batch-size ramp-up ([reference implementation](https://github.com/NVIDIA/Megatron-LM/blob/2a01637aa54ccdaf7ea9afc1f1b80f58c53d7f3c/megatron/core/num_microbatches_calculator.py#L233-L237)): gradually increases the per-device batch size in stages from a smaller starting value up to the final target, rather than starting training at full batch size immediately.

| Param | Purpose | Options / meaning | Deep Dive |
|---|---|---|---|
| `enable_rampup_batch_size` | Master switch for batch-size ramp-up. | `true`/`false`, default `false`. | [[enable_rampup_batch_size]] |
| `per_device_batch_size_start` | Starting batch size for the ramp-up. | Float, default `4.0`. | [[per_device_batch_size_start]] |
| `per_device_batch_size_increment` | How much to increase the batch size by at each ramp-up stage. For a clean ramp-up, `(per_device_batch_size - per_device_batch_size_start)` should be evenly divisible by this increment. | Float, default `2.0`. | [[per_device_batch_size_increment]] |
| `global_rampup_samples` | Target number of training samples to process during the entire ramp-up phase. No strict constraint on the value — just needs to be positive. | Integer, default `500`. | [[global_rampup_samples]] |

## Notes to self

- `dataset_type` is the fork point for this whole section — only one of the TFDS / HF / Grain / OLMo param blocks actually applies at a time, based on this single switch.
- `per_device_batch_size` being a _float_ (not int) is intentional — it's what makes `expansion_factor_real_data` and the ramp-up mechanism work, since effective batch size is computed from this value rather than being a hardcoded integer.
- Grain is clearly the most actively developed pipeline here, given how much deeper its param surface goes (worker tuning, mixture configs, elastic iteration) compared to TFDS or HF — worth defaulting to Grain for any pretraining-scale work where you need serious data-loading throughput.
- `max_segments_per_seq` is one of those params that looks like a training-quality knob but is really about avoiding a TransformerEngine crash/corruption bug — good example of why reading the actual inline comments (not just param names) matters in this file.
