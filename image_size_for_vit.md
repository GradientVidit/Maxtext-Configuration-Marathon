## 1. Why does `image_size_for_vit` exist?

Vision Transformers operate on fixed-size or pre-partitioned square image inputs (e.g. $896 	imes 896$ or $336 	imes 336$). The image resolution directly determines the 2D grid dimensions ($H/P 	imes W/P$), the total number of visual tokens injected into the LLM, and the static positional embedding table shape.

```text
Raw Image (H x W) ──► Resize/Crop to (image_size_for_vit x image_size_for_vit)
                             │
                             ▼
                      Patchify (Patch Size P)
                             │
                             ▼
                Total Patches N = (image_size_for_vit / P)^2
```

`image_size_for_vit` defines the canonical square pixel resolution expected by the Vision Transformer encoder.

---

## 2. Architectural Impact

For an image size of $896$ and patch size of $14$:

ight) 	imes \left(rac{896}{14}

If spatial downsampling (e.g., $2 	imes 2$ pixel shuffle) is applied, this reduces to $1024$ tokens.

---

## 3. Options and Defaults

| Value | Target Model Family | Visual Token Count (Pre-Merge) |
|---|---|---|
| `896` (Default) | Gemma 3 / Gemma 4 | 4096 patches ($64 	imes 64$) |
| `336` | Llama 4 Vision / CLIP-Large | 576 patches ($24 	imes 24$) |
| `448` | Qwen2-VL / InternVL standard tile | 1024 patches ($32 	imes 32$) |

MaxText config default: `896` in `base.yml`. Note that model preset configs override this value per architecture.

---

## 4. Key Parameter Interactions

- **`patch_size_for_vit`**: Grid dimension $= \text{image\_size\_for\_vit} / \text{patch\_size\_for\_vit}$. Must divide evenly.
- **`max_target_length`**: Total LLM context length must accommodate the visual tokens generated by this image resolution plus text tokens.

---

## 5. What breaks if wrong?

- If `image_size_for_vit` does not match the pretrained ViT's expected positional embedding grid or patch stride, tensor shape mismatch exceptions will occur during positional embedding addition.
